SKALA 2.0

Zen Computer System · JKR Malaysia · Flutter frontend · BLoC · Laravel API by teammate

Project-monitoring app for Jabatan Kerja Raya (JKR). I own the Flutter side: role-based dashboards, site diaries, BHTB verification with e-signatures, i-Supervision photo uploads and PDF reports — integrated against the Laravel REST API my teammate builds.

Flutter BLoC REST API Firebase

My role

Flutter (frontend) developer in a two-person mobile team. I built the screens and BLoC state layer for five user roles — JKR officers, ministry, contractors, consultants and handover teams — and integrated 40+ endpoints from the Laravel backend: JWT login with refresh tokens, JKR SSO, site diaries, BHTB verification with signature capture, i-Supervision photos, push notifications and PDF reports.

Optimisation

Moved heavy filtering, sorting and CSV parsing into isolates, compressed and resized photos before upload, added paginated lazy-loading lists, shimmer placeholders, debounced search, and draft and session caches so field officers keep their work when connectivity drops. Also set up the iOS build — bundle IDs, pods, plugin registration — for TestFlight.

Outcome

One codebase running on iOS and Android, already pointed at JKR's production API, with roughly half of the repository's commits mine across the app's screens, API layer and config. BLoC keeps business logic separate from UI, so new features land on both platforms at once.

MyIBJKM

Zen Computer System · JKM Malaysia · Solo enhancement · Java · SwiftUI · PHP · MySQL

Enhancement of JKM's published citizen app, handled alone end-to-end: upgraded the native Android (Java) and iOS (SwiftUI) apps in Android Studio and Xcode, and built the new PHP endpoints the new features needed — disaster-relief aid (BWI) status and history, QR check-in status and app version checks — on JKM's existing MySQL system.

Java SwiftUI PHP MySQL Android Studio Xcode

Context

MyIBJKM is Jabatan Kebajikan Masyarakat's public app for citizens to manage family (KIR) records, evacuation-centre (PPS) check-ins and disaster-relief aid. It was already live on both stores when JKM asked for new aid features and a modernisation pass. I was the sole developer on the enhancement.

What I built

Backend: new vanilla PHP endpoints inside the app's module of JKM's system — BWI aid status and history, aid-recipient lists with PDF preview, QR check-in status, KIR status checks and a mobile version gate — plus a rework of the login, PDF, PPS, check-in/out and profile-update endpoints with prepared statements and signed session tokens. Mobile: upgraded both native apps — Android (Java) to target SDK 36 with Keystore-backed SQLCipher, an in-app update flow and a locked-down network config, and the iOS app in SwiftUI to match.

Outcome

Live on the App Store and Google Play. Handling every layer of the change — PHP, Android and iOS — meant one person could trace an issue from screen tap to SQL query, and JKM got the new aid features without spinning up a separate backend team.

Java SwiftUI PHP MySQL Volley Google Maps SQLCipher QR

MushroomMate

Final Year Project · Flutter · CNN · 350+ species · 95% accuracy · 2× Gold award

Flutter app that tells poisonous from edible mushrooms in real time using a Convolutional Neural Network trained on 350+ species — fully offline via TensorFlow Lite. Gold at Karnival Inovasi UMT 2024 and VI-BiiDE 2024, bronze at iIDEX 2024.

Flutter TensorFlow Lite CNN Figma

Problem

Foragers and hikers in Malaysia frequently encounter unfamiliar mushrooms — some edible, some lethally toxic. Existing identification apps require an internet connection, but cellular signal in dense forests is unreliable. Misidentification can kill.

Approach

Designed the app in Figma and StarUML, trained a custom CNN in Jupyter Notebook with TensorFlow on a dataset of 350+ mushroom species, then converted it to TensorFlow Lite and built the Flutter app around it — point the camera at a mushroom and get a classification in under a second, no signal required.

Outcome

~95% classification accuracy on the held-out test set. Presented and demoed publicly as a Final Year Project, then won Gold at Karnival Inovasi UMT 2024 and VI-BiiDE 2024. The offline-first approach proved that field-usable mobile AI is viable without cloud dependency.
