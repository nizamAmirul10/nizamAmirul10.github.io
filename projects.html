MushroomMate

FYP Project

350+ species classified · 95% accuracy

Problem

Foragers and hikers in Malaysia frequently encounter unfamiliar mushrooms — some edible, some lethally toxic. Existing identification apps require an internet connection, but cellular signal in dense forests is unreliable. Misidentification can kill.

Approach

Trained a custom Convolutional Neural Network on a dataset of 350+ mushroom species, optimized for on-device inference. Deployed it as a Flutter app that runs the model entirely offline — point the camera at a mushroom and get a classification in under a second, no signal required.

Outcome

~95% classification accuracy on the held-out test set. Final Year Project submission, presented and demoed publicly. The offline-first approach proved that field-usable mobile AI is viable without cloud dependency.

Tech Stack

AI/ML Flutter CNN

MyIBJKM

Published

iOS + Android · Native (separate codebases)

Problem

JKM Malaysia needed a public-facing app for citizens to manage assistance records, family details, and disaster-relief data (BWI / PPS), delivered with platform-native polish on both iOS and Android — and powered by a backend that could integrate with existing JKM systems via ODBC.

Approach

Built it end-to-end. Two separate native mobile codebases — iOS in SwiftUI (HIG-compliant), Android in Java (Material Design) — talking to a vanilla PHP REST API I wrote and maintain. The PHP layer (~30+ endpoints) handles authentication, geo-coordinate listings, PDF generation/preview, QR-code activity, check-in/check-out flows, and family record CRUD against JKM's database via ODBC. JSON in, JSON out, in Bahasa Malaysia where it matters.

Outcome

Live on App Store and Google Play with a backend I own. Each mobile platform feels genuinely native, not "ported." Full-stack ownership means I can debug from screen tap to database query — a faster feedback loop than splitting the work across separate teams, and exactly the kind of context recruiters look for in a mobile developer who can ship.

Tech Stack

SwiftUI Java PHP MySQL ODBC REST API iOS Android

SKALA 2.0

In Progress

iOS + Android · Single codebase · BLoC

Problem

Jabatan Kerja Raya (JKR) — Malaysia's Public Works Department — needed to track infrastructure project status and progress in real time. Field officers and supervisors were spread across both iOS and Android devices, and the previous workflow couldn't keep status updates synchronized. Each platform divergence meant duplicated bugs and longer delivery cycles.

Approach

Chose Flutter with the BLoC (Business Logic Component) pattern to ship one codebase to both platforms while keeping business logic cleanly separated from UI. BLoC's stream-based state management made real-time status updates predictable and testable. Single codebase = changes ship to both platforms simultaneously.

Outcome

In-progress build delivering near-native performance on both iOS and Android from a single codebase. The BLoC architecture cut state-related bugs significantly and made feature additions faster — typical for a government project where reliability matters more than novelty.

Tech Stack

Flutter BLoC iOS Android
